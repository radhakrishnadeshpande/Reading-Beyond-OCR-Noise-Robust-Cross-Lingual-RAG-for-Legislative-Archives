Reading Beyond OCR Noise: Robust Cross-Lingual RAG for Legislative Archives

CVIT, International Institute of Information Technology, Hyderabad, India

Read the paper Get the code Cite

Abstract

Decades of Indian parliamentary records survive only as degraded, multi-column scans that mix Hindi, Punjabi and English. On these pages, OCR failure is the main obstacle to finding information.

We present an end-to-end framework that pairs vision-based layout segmentation and multi-script OCR with an agentic retrieval-augmented generation (RAG) pipeline. An iterative loop checks the retrieved evidence, rewrites the query when it falls short, and searches again before answering. On the 200,000-page Punjab Vidhan Sabha archive, the system outperforms standard text-only baselines.

Pipeline

Queries are embedded in their own language, so Punjabi questions can retrieve English pages without translation. Answers come back in the language of the question.

  1. Read the page images

    A fine-tuned YOLO layout model splits multi-column pages into regions. A CRNN recognizer reads each region.

  2. Index with multilingual embeddings

    BAAI/bge-m3 embeds the text chunks and metadata into a ChromaDB vector store.

  3. Retrieve and check

    The top-5 chunks come back by cosine similarity. An evaluation LLM decides whether they are enough to answer the question.

  4. Rewrite and retry

    If not, a rewriting LLM rephrases terms that OCR errors may have hidden, keeping the original intent, and retrieval runs again.

  5. Answer from evidence

    A generation LLM answers in the user’s language, grounded in the validated pages.

The archive

Records come from bound volumes digitized over several decades at pvs.neva.gov.in: proceedings, debates, starred and unstarred questions, budgets, committee reports and notices. Pages from the 1950s and 1960s show faded type, ink bleed-through and skew. Recent pages are cleaner but still dense and multi-column.

The evaluation set is stratified by decade, script and document type, so results reflect the whole archive and not only its cleaner end. It has 1,000 pages and 200 gold question–answer pairs, plus 20 hand-transcribed pages for OCR ground truth.

Limitations

Severe OCR errors can still affect dense retrieval and entity matching. The agent loop and LLM sufficiency checks add latency compared with single-pass retrieval. Complex financial tables can lose their hierarchy when converted to text chunks. Future work targets OCR robustness, lower latency and table structure.
